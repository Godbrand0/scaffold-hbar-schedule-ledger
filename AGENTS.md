# Agent instructions

Briefing for coding agents in this repository (Claude Code, Cursor, Codex). `CLAUDE.md` points here.

**Schedule Ledger** is a Scaffold-HBAR template: a Foundry contract that pays itself on a schedule through the
Hedera Schedule Service (HSS, `0x16b`), a Rust indexer that tracks every run through the mirror node, and a Next.js
dashboard. Read `README.md` first for the design and the reasons behind it.

## Commands

```bash
yarn install
yarn test                       # foundry + frontend + indexer tests, all offline
yarn lint                       # eslint + forge fmt + cargo fmt/clippy
yarn foundry:test               # forge test (mock HSS)
yarn foundry:deploy:testnet     # needs a funded keystore: yarn foundry:account:generate
yarn indexer:test | indexer:build | indexer:start
yarn next:dev | next:build | next:test | next:check-types
```

Use `yarn`. Rust is only needed for `indexer:*`; without `cargo` those scripts warn and skip (except `start`).

## Rules that are easy to get wrong

- **Events are a contract between three codebases.** Changing an event in `RecurringPayments.sol` means updating
  the `sol!` block in `events.rs`, the `LedgerEvent` enum and `apply_to_state` in `store.rs`, and the types in
  `packages/nextjs/utils/schedule-ledger/indexer.ts`, plus tests in each.
- **HSS never reverts.** `scheduleCall` returns `(int64 code, address)`; `22` is success. Always check both values
  and always call `hasScheduleCapacity` first. Never book from a `DELEGATECALL` frame
  (hiero-consensus-node#27263).
- **Units.** `msg.value` inside the EVM is tinybar (1 HBAR = 1e8). Wallet `value` is 18-decimal weibar
  (1 tinybar = 1e10). Use `tinybarToWeibar` in the frontend. Amounts reach the API as tinybar strings.
- **HSS does not exist on Anvil or forks.** Tests etch `MockHederaScheduleService` at `0x16b`. `vm.etch` copies
  code, not storage, so mock defaults must be zero values.
- **Mirror node timestamps** are `seconds.nanoseconds` strings. Compare them as integers (`parse_timestamp`), never
  as strings.
- Do not commit `.env` files, keystores or private keys. `.gitignore` covers `.env`.

## Adding a feature

1. Contract change plus Forge tests (`yarn foundry:test`).
2. If events change: indexer decoder, store, API, then an end-to-end test in `tests/pipeline.rs`.
3. Frontend types and UI; keep pure logic in `utils/` with a Vitest test.
4. Run `yarn lint && yarn test` before finishing.
